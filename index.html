1. What is a terminal

A terminal is a way to control your device by typing instructions instead of tapping icons. Every app on your phone or computer is really just a program running underneath a friendly picture-based interface. A terminal skips the pictures and lets you talk to that underlying system directly, in text.

When you open Termux, you're greeted with a prompt, usually something like:

~ $

The ~ shows your current location. The $ means the terminal is ready and waiting for you to type something.

You type an instruction, called a command, and press enter. The terminal reads it, does exactly what it says, and shows you the result as text.

The most important mindset shift: nothing happens until you press enter. You can type and even make mistakes safely, as long as you haven't hit enter, nothing has actually run yet.

2. Reading a command

Some commands are complete on their own, nothing else needed:

exit
clear
history

Each of these runs by itself. No extra steps, no extra information required.

The same idea exists outside a terminal too. If someone told you to blink, you'd know exactly what to do, nothing else needs to be said.

3. Some commands require more

Some commands work on their own, like we've already seen. Others need extra information attached before they'll do anything useful. Here are a few real ones:

  • cd needs a folder to move to
  • cat needs a file to show
  • mkdir needs a name for the new folder
  • rm needs a file to remove
  • ping needs an address to check

The same idea in real-world terms:

  • look needs somewhere to look
  • feel needs something to feel
  • taste needs something to taste
  • remove needs something to remove
  • check needs something to check

Each of these follows the same shape: command, then argument.

cd Documents

4. Introducing arguments aka -steps

Other commands need extra steps to get the results you want. For example, if you are told to look at something, you also need to know what you are being told to look at.

command -flag argument
look -at this

look is the command. -at is the flag. this is the argument, the specific thing being looked at.

Here's a real one:

ls -l Documents
  • ls is the command
  • -l is the flag
  • Documents is the argument

Important note to take: a flag sometimes needs an argument to make sense, the same way "look" needs something to look at. Not every flag needs one, but when it does, the argument comes straight after it, separated by a space.

5. List of terminal abbreviations

Now we know the difference between a command and a flag, let's first see a list of flag abbreviations to get a better understanding of each, before trying an example of your choosing in the Termux terminal.

  • -l = list
  • -h = help
  • -v = verbose (or version, depending on the command)
  • -a = all
  • -r = recursive (or remove, depending on the command)
  • -f = force (or file, depending on the command)
  • -n = number
  • -s = sensor
  • -o = output
  • -p = port (or package, depending on the command)
  • -d = delete (or directory, depending on the command)

Important note to take: not every command agrees on what a letter means, the same flag can mean something different depending on the command it's attached to. If you're ever unsure, adding --help after a command will usually show you exactly what its own flags do.
